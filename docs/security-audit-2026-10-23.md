# Проверка приватности TYPOS — 23 октября 2026

Проверены текущий код, 14 коммитов и 472 объекта файлов доступной истории Git,
настройки GitHub, три сервиса Railway, работающие контейнеры и публичные HTTP-ответы.
Значения секретов в отчёт не включены. Это ручная проверка перечисленных границ,
а не доказательство отсутствия всех возможных уязвимостей.

## Что доступно извне

| Адрес | Фактический ответ |
| --- | --- |
| `typos-production.up.railway.app/` | 404 от Railway, приложение не отдаётся |
| `typos-vault-production.up.railway.app/` | 200, короткая статическая страница TYPOS storage, без скриптов |
| `typos-mcp-production.up.railway.app/` | 404, интерфейса приложения нет |
| `typos-mcp-production.up.railway.app/healthz` | 200, только состояние процесса |

Репозиторий `robloxlover44/typos` приватный. GitHub Pages выключен,
homepage не задан. В доступном списке GitHub deployments указаны только Railway.
На сервисе `typos` остался публичный домен и источник GitHub, хотя сейчас он не
отдаёт сайт: будущий деплой может изменить это. Отсутствие неизвестных сторонних
копий или других хостингов по этим проверкам установить нельзя.

Приложение собирается локально в Tauri, также поддерживает PWA. Подключённый
удалённый vault хранится на Railway; локальная копия и настройки подключения —
в IndexedDB приложения. Это не режим «все данные только на ПК».

На момент чтения auth-файла: три public-клиента, ноль активных grants,
ноль сохранённых client secrets. После этого браузерная проверка создала ещё
одного public-клиента, но разрешение не выдавала и личный ключ не вводила.
`client_id`, vault ID, домены и идентификаторы Railway сами по себе не секреты.

Дополнительные административные секреты находятся вне проекта:
`C:\Users\User\.railway\config.json` и приватный SSH-ключ
`C:\Users\User\.ssh\id_ed25519`. Они управляют инфраструктурой; их значения
не читались и не выводились. Публичный SSH-ключ не является секретом.

В GitHub Actions не настроены repository secrets и variables. В рабочем дереве
отслеживаемых и неигнорируемых файлов и в доступной истории не найдены совпадения
с действующими ключами или строки проверенных форматов приватных ключей,
GitHub/OpenAI-токенов и реальных ссылок TYPOS. Игнорируемые сборки, недоступные
ветки, резервные копии, внешние чаты и вся файловая система ПК не сканировались.

## Подтверждённые проблемы и существенные риски

1. **Нет сквозного шифрования.** Сервер хранит читаемые Markdown и другие файлы;
   ключи устройств также хранятся открыто. HTTPS защищает передачу, но не скрывает
   данные от работающего storage/MCP или администратора инфраструктуры. При
   вызове инструментов выбранные данные передаются ИИ-клиенту.
2. **Один ключ волта на всё.** В storage зарегистрировано только устройство
   `default`. Один и тот же ключ используется конфигом Codex, локальным плагином
   и MCP на Railway. У него полный доступ на чтение/запись; отдельного read-only
   режима и независимого отзыва только MCP сейчас нет. Прямой WebDAV поддерживает
   DELETE, включая удаление вне корзины; ограничение MCP «только корзина» не
   ограничивает владельца самого ключа.
3. **Локальный MCP читает произвольные файлы по переданному пути.**
   `mcp/tools.ts:61` и `add_project_file` не ограничены выбранной папкой. ИИ,
   вызвавший эти инструменты, может скопировать доступный процессу файл в vault
   и затем прочитать его. Это действующая возможность плагина, опасная при
   ошибочном разрешении или prompt injection. В удалённых HTTP-схемах эти
   аргументы и `add_project_file` исключены.
4. **Локальный NodeFsAdapter выходит через junction/symlink за пределы vault.**
   Подтверждено на собственной временной папке: `readText('jump/marker.txt')`
   прочитал безвредный маркер снаружи корня. `abs()` проверяет строку, но не
   реальный путь. Дополнительно `./.typos-server/server.json` обходит запрет
   первого сегмента и читает тестовый файл состояния. Это локальный адаптер;
   публичный storage использует другую проверку с realpath.
5. **Tauri также не проверяет реальные пути через ссылки.**
   `src-tauri/src/vault.rs:68` проверяет сегменты и Granted-корень, затем команды
   используют обычные `fs::read`/запись. Защиты от дочернего junction наружу нет.
   Вывод основан на коде; эксплуатация через интерфейс собранного exe не проводилась.
6. **Обход CSP HTML-тулз.** `withCsp()` ищет `<head>` регулярным выражением,
   включая HTML-комментарии. На безвредном примере с `<!-- <head> -->` защитный
   meta-тег попал в комментарий; HTML-парсер подтвердил ноль активных CSP-тегов.
   Сетевая политика такого документа не устанавливается. Сам iframe остаётся
   sandbox без allow-same-origin: полного выхода в DOM приложения этот тест
   не показал. Даже обычная политика разрешает inline/eval, внешние CDN и popups;
   она не означает «никакой сторонний код никогда не запускается».
7. **У основного окна Tauri отключена CSP:** `security.csp = null`.
   При отдельной XSS это увеличивает последствия: код основного окна имеет
   доступ к состоянию приложения и разрешённым IPC-командам. Сама XSS в
   редакторе этой проверкой не установлена; Mermaid настроен в strict-режиме.
8. **Storage работает от root внутри контейнера.** Проверено по UID процесса.
   Сейчас HTTP-метода исполнения команд не найдено, но последствия будущей RCE
   или файлового обхода будут выше. Основной MCP-процесс — UID 1000, подтверждено
   по `/proc/1/status`; стартовая подготовка тома выполняется от root.
9. **CLI storage печатает полную ссылку с ключом при запуске.** Работающий сервер
   запускается через этот entrypoint; его исходник совпал с локальным по SHA-256.
   В доступных запрошенных логах совпадений не найдено, поэтому наличие или
   отсутствие ключа во всех старых логах/экспортах не доказано. Это канал утечки
   для тех, кто имеет доступ к журналам, а не публичная выдача ключа браузеру.
10. **Отказ в обслуживании.** OAuth имеет общие лимиты для одного владельца:
    посторонние запросы могут временно исчерпать их; регистрация ограничена 100
    клиентами. У storage ограничения по IP могут объединять клиентов за прокси.
    Есть лимит размера одного файла, но нет прикладной общей квоты, лимита числа
    файлов и надёжной общей защиты CPU/памяти. Атаки нагрузкой не проводились.
11. **Локальная загрузка изображений делает произвольный HTTP(S) GET**, в том
    числе по перенаправлениям, без запрета private IP. Это риск обращений к
    локальной сети через ИИ. Размер ответа проверяется после `arrayBuffer()`.
    В удалённом MCP внешние URL запрещены; там остаются риски декодирования
    специально подготовленных изображений после авторизации.
12. **Избыточные зависимости образа и известные DoS advisories.**
    `npm audit --omit=dev` сообщил 7 high и 1 moderate по восьми пакетам:
    `braces`, `micromatch`, `fast-glob`, `@shadcn/registry`, `@ts-morph/common`,
    `ts-morph`, `shadcn`, `ip-address`. Это главным образом две цепочки причин,
    а не восемь независимых удалённых атак. High-цепочка идёт через CLI shadcn;
    её доступность через HTTP не установлена. `ip-address` также входит через
    express-rate-limit, но заданные OAuth keyGenerator не разбирают адрес клиента.
    В образ ставятся и devDependencies. Автоматический `audit fix --force`
    не запускался.

Источники advisories:
[braces / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm),
[ip-address / CVE-2026-111997](https://github.com/advisories/GHSA-rxp7-6hxx-x8q5).

Потенциальная гонка realpath → файловая операция storage остаётся при наличии
другого процесса, меняющего ссылки на диске. Публичный WebDAV не создаёт symlink;
эксплуатация этой гонки не проверялась. Компрометация ПК, аккаунта Railway/GitHub,
браузерного профиля или зависимостей также меняет границу доверия: это не
изолированные и не зашифрованные от владельца процесса секреты.

## Что показала проверка публичного волта

- Без ключа `/.typos/info`, `/files/`, файл состояния и `/.git/config` вернули 401.
- С действующим ключом `.typos-server/server.json` и вариант регистра вернули 404.
- Корень отдаёт фиксированный HTML без скриптов и пользовательских подстановок.
- Собственный временный HTML со скриптом-маркером был отдан как
  `application/octet-stream`, с `X-Content-Type-Options: nosniff` и
  `Content-Security-Policy: sandbox; default-src 'none'`; без ключа — 401.
- Временный файл удалён после проверки. Пользовательские заметки не менялись.
- Сервер не импортирует, не запускает и не интерпретирует загруженные файлы.

По проверенным маршрутам простое открытие адреса волта не запускает код из
хранилища. Это не гарантия против неизвестной уязвимости Node/браузера или
скомпрометированного контейнера. Файл, вручную скачанный и запущенный пользователем,
и HTML-тулза, открытая внутри TYPOS, — другие сценарии, с рисками выше.

## Приоритет дальнейших исправлений

Сначала ограничить чтение локальных файлов MCP и закрыть junction/state-alias
обходы; исправить вставку CSP. Затем выделить MCP собственный device key,
убрать печать ключа из startup-логов и снизить права storage. После этого
укреплять Tauri CSP, ограничения нагрузки, зависимости и политику HTML-тулз.
Для требования «облако не может прочитать заметки» нужна отдельная архитектура
шифрования; сейчас такого свойства у проекта нет.

В ходе этой проверки настройки и код продукта не менялись. Исправление отдельной
ошибки OAuth-формы из предыдущей задачи уже развернулось: настоящий браузер
теперь доходит до проверки намеренно неверного ключа вместо Origin-403.
